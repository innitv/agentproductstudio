# subsystem-audit — плагин: переносимая методология аудита подсистемы

Как проводить тщательный, доказательный аудит части системы (агенты, стек, репо-карта, конфиг, слой кода) по повторяемому шаблону. Упаковано так, чтобы жить **в одном месте** (этот репозиторий, под git) и раздаваться всем проектам через junction из `~/.claude/skills/subsystem-audit`.

## Зачем

Методология аудита — это переносимое «как делать», а не проектный факт: она одинаково работает в любом репозитории. Раньше она лежала как feedback-память проекта (`working-style-audits`) — «не на своём слое»: память привязана к проекту, а процедура нужна везде. Плагин ставит её на правильный слой.

Инженерные эвристики (§6 skill'а) вынесены из проектных аудитов агентной системы: «всё, что не проверяется машиной, дрейфует», «грепни, кто читает поле, до отказа от риска семантики», «сверься со списком отклонённого перед внедрением дешёвых улучшений из ресёрча» — они переносимы и экономят часы на ложных ветках.

## Что внутри

| Skill | О чём | Когда сработает |
|---|---|---|
| `/subsystem-audit:audit` | Повторяемый шаблон: единица аудита (роль/сильные/пробелы + GitHub-сравнение по реальным URL), верификация находок первоисточником, параллелизм со сборкой синтеза оркестратором, отчёт в файл + P0/P1/P2 в чат, запрет молчаливых структурных правок, инженерные эвристики против ложных находок и дрейфа | Любой аудит/ревью подсистемы, «проверь/оцени/улучши X», сравнение с best practice, поиск пробелов |

## Установка

Junction из пользовательского skills-каталога ставится и чинится одной командой из студии:
```bash
yarn plugin:link subsystem-audit
```
Скрипт идемпотентен, `yarn plugin:link --check` — только диагностика. После создания junction **перезапусти Claude Code**, чтобы новый плагин подхватился (правки уже существующего плагина действуют в сессии без рестарта).

## Правило поддержки

Новое переносимое знание об аудите/ревью идёт **сюда**, а не в память проекта и не напрямую в `~/.claude/skills/`. Проектно-специфичное (конкретный отчёт, конкретная подсистема, node id) остаётся рядом с проектом. Копий не заводить — разъезжаются всегда.
