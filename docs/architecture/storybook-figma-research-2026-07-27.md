# Ресёрч: Storybook и Figma — кто источник правды

Дата: 2026-07-27
Тип: доказательный ресёрч под решение (не продуктовый run)
Метод: четыре параллельных сбора (токены / интеграции / бенчмарк DS / визуальная приёмка), синтез собран оркестратором
Повод: вопрос «а если отказаться от Figma и делать сразу в Storybook»

## 0. Краткий ответ

Отказываться надо не от Figma, а от **роли Figma как источника правды**. Ресёрч подтвердил это шестью независимыми примерами и одновременно **опроверг** промежуточную гипотезу «Figma как автоматическое зеркало DS»: в индустрии зеркало компонентов не генерирует никто.

Три вывода, которые меняют план:

1. **6 из 6 зрелых DS держат токены в репозитории.** Figma не является источником правды для токенов ни у кого из проверенных.
2. **0 из 6 генерируют Figma-библиотеку компонентов из кода.** Её ведут люди-дизайнеры параллельно, с собственным релизным циклом.
3. **Всё, что у больших автоматизировано, нам закрыто по тарифу** (Code Connect — Org/Enterprise; Variables REST API — Enterprise + Full seat). Доступен ровно один путь: нативный DTCG-импорт руками.

Следствие для студии: у Carbon/Primer/Fluent есть штат дизайнеров, физически ведущий Figma-кит. У нас — один человек и агенты. Значит наш выбор жёстче, чем у них: **Figma-кит компонентов не вести вообще**.

## 1. Ось A — токены код ↔ Figma

### Главный факт

С ноября 2025 у Figma есть **нативный импорт/экспорт DTCG** прямо в Variables view (drag-and-drop JSON, один файл = один mode).
Источник: [help.figma.com — Modes for variables](https://help.figma.com/hc/en-us/articles/15343816063383-Modes-for-variables), контекст релиза — [Schema 2025 recap](https://www.figma.com/blog/schema-2025-design-systems-recap).

- REST API не участвует — это UI-операция, лимит 6 чтений/мес не расходуется.
- Требование: любой платный план (для modes), доступ `can edit`. **Enterprise не нужен.**
- Ограничение: при обновлении существующего mode новые переменные **не создаются** — обновляются только совпавшие по имени и типу. Типы: color, dimension, font family, duration, number, string.

### Что отпадает и почему

| Инструмент | Вердикт | Причина |
|---|---|---|
| Figma Variables REST API | ❌ | «must have a Full seat in an Enterprise org» — [дока](https://developers.figma.com/docs/rest-api/variables). Двойной блокер: план + seat |
| Terrazzo | ❌ | Variables требуют Enterprise; направление Figma→код (обратное нужному); [issue #501](https://github.com/terrazzoapp/terrazzo/issues/501) про экспорт висит без ответа год |
| Supernova | ❌ | Figma объявлена authoritative source, редактирование импортированного запрещено by design — противоречит цели |
| Specify | ❌ | [Закрылся в октябре 2024](https://specifyapp.com/blog) |
| Tokens Studio | ⚠️ | Работает без Enterprise (Plugin API), но multi-mode и git-синк — платно (от €17/мес), запуск руками |

### Что работает у нас

- **Style Dictionary** ([amzn/style-dictionary](https://github.com/amzn/style-dictionary), 4752★, v5.5.0 от 2026-06-21) — генерация CSS/TS из DTCG. Оговорка: встроенного формата `json/dtcg` нет, для отдачи DTCG наружу нужен конвертер (`convertToDTCG`).
- **Нативный DTCG-импорт Figma** — основной и единственный дешёвый мост код→Figma.

**Честный вывод оси:** бесплатного способа синхронизировать код→Figma **без участия человека** не существует. Максимум — «CI сгенерировал DTCG, человек импортировал одним действием».

## 2. Ось B — интеграции Storybook ↔ Figma

| Инструмент | Направление | Вердикт |
|---|---|---|
| [story.to.design](https://story.to.design/) | Storybook → Figma, компоненты с variants | ⚠️ Единственный настоящий «зеркальщик». $149/мес. **Матчит только legacy Figma Styles (colors/text), не Variables, не Tokens Studio** — [дока](https://story.to.design/docs/matching-styles). Это Figma-плагин: синк запускает человек кликом, из CI нельзя |
| [Figma Code Connect](https://github.com/figma/code-connect) | Метаданные код→Figma | ❌ По тарифу: «Organization and Enterprise plans, full Design or Dev Mode seat» |
| [@storybook/addon-designs](https://github.com/storybookjs/addon-designs) | Никуда, визуальная привязка | ✅ Дёшево, 950★, живой. Просто врезает Figma-фрейм в панель Storybook |
| Storybook Connect (Chromatic) | Привязка Figma→Storybook | ⚠️ Год без обновлений, требует Storybook в Chromatic |
| Figma MCP write | Обе стороны, агентная запись | ⚠️ Единственный путь, где пишет агент, а не человек. Но это запись «по инструкции», не детерминированный синк |

**Ключевое разделение:** всё от ‹div›RIOTS — плагины, то есть ручной клик в Figma-приложении. REST API канвас не пишет в принципе (единственный write-эндпоинт — Variables, и он Enterprise).

## 3. Ось C — бенчмарк зрелых DS (главная ось)

| DS | Токены — где правда | Figma из кода? | Storybook | Чем ловят расхождение |
|---|---|---|---|---|
| [Carbon](https://github.com/carbon-design-system/carbon) 9310★ | Репо, DTCG: `packages/themes/src/dtcg/*.json` | **Нет** — кит ведут дизайнеры IBM | ✅ Публичный, основная витрина | Code Connect из CI (47 компонентов + 2000 иконок) |
| [Primer](https://github.com/primer/primitives) 397★ | Репо, JSON5 + Style Dictionary | **Частично** — `build:figma` пишет JSON **на диск**, HTTP-вызовов нет | ✅ Публичный | Code Connect из CI + VRT + `diff-design-tokens.yml` |
| [Spectrum](https://github.com/adobe/spectrum-design-data) | Репо, своя JSON-схема | **Нет** | ✅ Через доксайт | Chromatic + token-diff в PR |
| [Fluent](https://github.com/microsoft/fluentui) 20172★ | Репо, TypeScript | **Нет** — кит ведут руками | ✅ storybooks.fluentui.dev | VRT (`pr-vrt.yml`, `vrt-baseline.yml`) |
| Polaris | Репо, TypeScript | **Нет** | Свой сайт | ⚠️ Репо **архивирован 06.01.2026**, React-реализация deprecated |

### Прямой ответ на ключевой вопрос

**Ни у одной из шести систем Figma-библиотека компонентов не генерируется из кода.** Автоматизированы только две вещи, и обе не «рисуют» библиотеку:

1. **Code Connect** — меняет, какой сниппет видит разработчик в Dev Mode. Не геометрию.
2. **Токены как файл-артефакт** — Primer собирает `dist/figma/*.json`, кто-то потом импортирует.

Единственный найденный случай полностью автоматического push по REST API — [пайплайн Intuit](https://medium.com/@NateBaldwin/synchronizing-figma-variables-with-design-tokens-3a6c6adbf7da). Автор сам перечисляет, почему это не стало нормой: у Figma API нет управления изменениями (переменные меняются молча, дизайнеры не уведомляются), нет governance-стоп-крана, приходится вести свой маппинг Figma UID.

**Автоматической проверки «Figma совпадает с кодом» нет ни у кого.** Это ручное ревью и дисциплина. Расхождение все ловят **на стороне кода**: визуальная регрессия, диффы токенов в PR, контрастные проверки.

### Побочная находка

Polaris React архивирован и помечен deprecated; Shopify мигрировал на web components. Кодовая реализация DS смертна и мигрирует между технологиями, а Figma-библиотека переживает конкретный фреймворк. Это аргумент **не против** переноса правды в код, но за то, чтобы источником правды был **слой токенов и контрактов (DTCG)**, а не конкретная React-библиотека.

## 4. Ось D — визуальная приёмка вместо сверки с Figma

### Рекомендуемый стек

**Storybook (каталог состояний) → Playwright `toHaveScreenshot` → JSON reporter.**

Почему Playwright, а не Chromatic:
- Полный машинный отчёт локально, без облака: `reporter: [['json', { outputFile }]]`, в `attachments` — пути к `-expected` / `-actual` / `-diff`.
- Chromatic/Percy дают только бинарный вердикт (exit code), per-story процент наружу не отдают, а приёмка baseline — действие в веб-UI. Плюс выгрузка снапшотов в облако = внешняя запись, то есть approval-гейт по [CLAUDE.md §7](../../CLAUDE.md) — человек возвращается в цикл ровно там, где мы его убирали.

Схема вердикта для агента:
```
status per story     ← results.json (бинарный, порог декларативный через maxDiffPixels)
масштаб дефекта      ← «N pixels» из error.message (точное целое; ratio округлён до 2 знаков, бесполезен)
артефакт для разбора ← attachments[].path
```

### 🔴 Критичное ограничение реализации

**Baseline-скриншоты нельзя снимать на Windows-хосте.** Дока Playwright: «run tests in the same environment where the baseline screenshots were generated»; имя снапшота содержит платформу (`-chromium-darwin.png`), то есть Windows-baseline на Linux-CI даст не diff, а *новый* снапшот.

Хуже: [issue #20097](https://github.com/microsoft/playwright/issues/20097) — расхождение шрифтового рендеринга ломало сравнение **между двумя macOS-машинами одинаковой конфигурации**. «Та же ОС» — недостаточное условие, нужен идентичный образ.

Правило подсистемы: `--update-snapshots` разрешён **только** внутри пиннутого контейнера (`mcr.microsoft.com/playwright:v1.62.0-noble`). Иначе агент без человека в цикле начнёт принимать мусорные baseline — это худший из возможных отказов.

### Что Storybook даёт сверх Figma

| Слой | Чем | Есть в Figma? |
|---|---|---|
| Интеракции (play functions) | Storybook Vitest addon | ❌ невозможно |
| Accessibility (axe-core) | A11y addon, `test: 'error'` валит сборку | ❌ невозможно |
| Состояния компонента | Каталог сторей | ⚠️ только статичные фреймы |
| Пиксельный diff | Playwright (внешний к Storybook) | ⚠️ через ручную сверку |

**Поправка к распространённому ожиданию:** Storybook «из коробки» визуальную регрессию **не делает** — Vitest addon даёт smoke + play, пиксельный вердикт даёт отдельный инструмент.

### Агентная петля

[storybookjs/mcp](https://github.com/storybookjs/mcp) — официальный MCP-сервер команды Storybook, ~264★, активная разработка. [Дока](https://storybook.js.org/docs/ai/mcp/overview) описывает «self-healing loop that helps ensure the quality of the generated UI without requiring you to intervene»: генерирует → гоняет тесты → чинит → перегоняет. Тулы: `get-changed-stories`, `preview-stories`, `run-story-tests`.

**Оговорка:** `run-story-tests` — компонентные и a11y-тесты, **не визуальная регрессия**. Пиксельный слой в официальную петлю не входит.

**Готового публичного образца «LLM генерирует UI и проверяет себя визуально» не найдено.** Поисковая выдача по теме — вендорский маркетинг, не воспроизводимые пайплайны. Связку придётся собрать самим; все три кирпича по отдельности зрелые и документированы first-party.

## 5. Синтез: что это значит для студии

### Что подтвердилось

Направление «источник правды → код» — это индустриальная норма, а не эксперимент. Наш текущий расклад (правда в Figma, код — дрейфующая копия) идёт против всех шести проверенных систем.

### Что опровергнуто

Промежуточная гипотеза «Figma как автоматическое зеркало DS» ресёрчем **не подтверждена**: зеркало компонентов не строит никто, а доступные нам инструменты для этого либо платные и ручные (story.to.design), либо закрыты по тарифу (Code Connect).

При этом у Carbon/Primer/Fluent Figma-кит ведут штатные дизайнеры. У нас такого ресурса нет. Значит копировать их гибрид нельзя — надо выбрать более жёсткий вариант.

### Целевая раскладка

| Слой | Источник правды | Figma |
|---|---|---|
| Токены | DTCG-JSON в git → Style Dictionary | Зеркало через нативный импорт, вручную, по необходимости |
| Компоненты | Storybook (код) | **Не ведём кит вообще** |
| Экраны | Composition stories | Черновик направления на `04-design`, выбрасывается после |
| Приёмка | Playwright + Vitest + a11y, в Docker | Не участвует |

Figma сохраняет ровно две роли: **дивергентный черновик** (дёшево ошибиться до кода) и **разовый показ человеку**. Обе — до кода или в сторону от него, ни одна не требует поддержания синхронизации.

## 6. Приоритеты

**P0 — решения, без которых нельзя начинать**

1. Проверить, есть ли у аккаунта `can edit` хоть к одному Figma-файлу. Нативный DTCG-импорт требует edit-доступа; View seat права на редактирование не имеет. Прямой цитаты «View seat cannot import variables» не найдено — это вывод, а не факт, и его надо проверить практикой.
2. Зафиксировать правило Docker-baseline для скриншотов до написания первого теста. Задним числом это чинится перегенерацией всех baseline.

**P1 — то, что даёт основную ценность**

3. Поставить Storybook в `apps/frontend` (сейчас его нет — только skill [ds-to-storybook](../../agent-pack/skills/ds-to-storybook/SKILL.md) и шаблон отчёта).
4. Перевести токены DS в DTCG-JSON в репозиторий + Style Dictionary.
5. Подключить [storybookjs/mcp](https://github.com/storybookjs/mcp) — он закрывает ровно ту половину петли (поведение + a11y), которую студия сейчас не проверяет вообще.

**P2 — отложенное**

6. story.to.design — только если появится потребность в Figma-ките для внешних людей. $149/мес, ручной клик, дыра в токенах. На старте не нужен.
7. reg-suit поверх Playwright-скриншотов — если понадобится структурированный per-image процент вместо бинарного статуса.
8. Перестройка контрактов пайплайна (`workflow.manifest.ts`, `route.config.ts`, контракты design-generator/frontend/qa-review, skills, тесты) — это структурное изменение, выносится на отдельное решение, молча не делается.

## 7. Границы доказательности

Подтверждено первоисточниками: тарифные ограничения Figma (дока разработчика + plans-and-features), пути к файлам токенов в репозиториях (обход дерева, не README), состав CI-workflow, поведение Playwright при кросс-платформенных диффах (дока + два реальных issue), состав тулов Storybook MCP.

**Не подтверждено, не выдаётся за факт:**
- Может ли View-seat выполнить нативный импорт переменных (вывод по смежным правам, прямой цитаты нет) — **это P0-проверка**.
- Реальное качество переноса story.to.design на живой DS — независимых разборов нет, только вендорские тестимониалы.
- Поддерживает ли story.to.design Figma Variables сегодня — дока молчит, что скорее «нет».
- Точная граница бесплатного тарифа Tokens Studio — страницы `/pricing` и `/starter-plus` противоречат друг другу.
- Часть выводов «не найдено» по Adobe/Fluent/Backpack получена обходом директорий, а не полнотекстовым поиском (GitHub code search требует авторизации): это отсутствие свидетельств, а не доказанное отсутствие.
- Строка про API у плана Organization на figma.com/pricing противоречит дока-разработчика и plans-and-features. Принят Enterprise как нормативный, но расхождение существует.
