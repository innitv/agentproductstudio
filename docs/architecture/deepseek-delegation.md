# Делегация в DeepSeek: что можно отдать и по какому признаку

Дата: 2026-08-06. Статус: рабочая раскладка, не норма студии.

Документ отвечает на один вопрос: какую работу имеет смысл выполнять в отдельной сессии Claude Code, переключённой на бэкенд DeepSeek, а какую нельзя отдавать туда ни при каких условиях.

## 1. Механизм

DeepSeek держит Anthropic-совместимый endpoint `https://api.deepseek.com/anthropic` и официальную инструкцию интеграции с Claude Code. Переключение делается переменными окружения, `claude` запускается как обычно.

Существенное ограничение механизма: `ANTHROPIC_BASE_URL` — одна переменная на процесс. Смешать «оркестратор на Opus + субагенты на DeepSeek» **внутри одной сессии нельзя**. Переключается вся сессия целиком, включая главный цикл. Поэтому режим работы — не «делегация части задач из продуктовой сессии», а **отдельный терминал под отдельный класс работ**.

Запуск: `tooling/scripts/claude-deepseek.ps1`.

## 3. Тест на пригодность задачи

Задача уходит в DeepSeek-сессию, только если проходит все четыре вопроса:

1. **Нужно ли смотреть на изображение?** Совместимый слой не поддерживает image/document content. Любая работа со скриншотом, макетом или визуальной сверкой отпадает сразу.
2. **Проверяется ли результат машинно?** Тест, валидатор, typecheck, схема. Если единственный контроль качества — суждение модели, задача остаётся на сильной модели.
3. **Даёт ли задача статус продуктовому артефакту?** Если да — отпадает: статус `success` по артефакту студии выдаётся под гейтами, которые слабая модель исполняет хуже.
4. **Покидают ли песочницу чужие данные?** Клиентские материалы А3 и всё, что относится к заказчику, во внешнего провайдера не уходят независимо от технической возможности.

## 4. Зелёная зона

### 4.1. Машинно проверяемая инженерия

Общее свойство: результат подтверждает не модель, а команда.

- **Починка падающих `yarn workflow:test-*`** — их 33. Тест сам и есть приёмка; ошибиться незаметно нельзя.
- **`yarn typecheck` после рефакторинга** — механическая правка типов по выводу компилятора.
- **Новый тест по образцу существующего** — в `runtime/typescript/` уже лежит 33 шаблона, задача сводится к переносу структуры.
- **Нормализация frontmatter в `.claude/skills/*/SKILL.md`** — проверяется `yarn workflow:test-skill-metadata`.
- **Приведение файлов к схемам `agent-pack/schemas/*.json`** — проверяется валидатором.
- **Массовые переименования и правки по шаблону** через репозиторий — с последующим `yarn qa:quick`.

### 4.2. Объёмное чтение с коротким выходом

Общее свойство: вход большой, ответ короткий. Именно здесь окупается 1M контекста по $0.14.

- **Инвентаризация `outputs/` перед уборкой** — 166 md-файлов. Вернуть таблицу «слаг / дата / стадии / незакрытые обязательства». Само решение об удалении принимается в основной сессии: удаление требует approval `delete_data`.
- **Разбор длинных машинных отчётов** — `reports/visual-regression/summary.json`, `test-results/mobile-acceptance/*.json`, логи playwright. Разбор JSON — да, разглядывание приложенных скриншотов — нет.
- **Первый проход поиска расхождений «правило заявлено — код не исполняет»** — массовые грепы маркеров по дереву. Синтез и вердикт собираются в основной сессии.
- **Разбор незнакомой библиотеки или чужого репозитория** — прочитать полсотни файлов и вернуть сводку по API.

### 4.3. Черновики без статуса

- Черновой перевод ru↔en крупных блоков.
- Переписывание длинной документации в заданном стиле — с последующей вычиткой здесь.
- Генерация фикстур и тестовых данных.

Любой такой выход получает статус `draft` и не закрывает стадию.

## 5. Красная зона

**Всё визуальное — нет vision.** Гейты человека 8.5a и 8.5b, `visual-diff`, `ui-craft:reference-check`, разбор скриншотов `vr:test`, сборка в Figma через `use_figma`. Это не вопрос качества модели: изображения физически не проходят через совместимый слой.

**Продуктовые стадии со статусом `success`.** Research findings, PRD, copy, screens. Причина в CLAUDE.md §9 и Anti-AI-Slop: выход модели без источников не является evidence. DeepSeek уже помечен `confidence: low` в research-адаптере ровно поэтому.

**External write.** Notion publish, Figma canvas write, git commit/push, deploy, изменение секретов. Approval-гейт — это то место, где цена пропуска максимальна, а исполняет его модель.

**Клиентские материалы.** Артефакты А3 и любые данные заказчика.

**Финальные вердикты аудита и ретро.** Первый проход сбора фактов — можно, вывод — нет.

## 6. Что ещё не проверено

Документация DeepSeek говорит, что совместимый слой не поддерживает MCP-tools. Это относится к серверным hosted-инструментам Anthropic API (параметр `mcp_servers`), а не обязательно к клиентским MCP Claude Code, которые ходят обычным tool call через stdio. **Эмпирически не проверено.** До проверки считать, что Figma/Notion/Tavily MCP в DeepSeek-сессии недоступны.

Проверка стоит одной команды в DeepSeek-сессии: запросить `mcp__tavily__tavily_search` и посмотреть, дойдёт ли вызов.

Также не проверено на нашем материале: качество следования правилам `CLAUDE.md`. Файл загрузится в контекст, но исполнение гейтов слабой моделью — отдельный вопрос, и первые запуски стоит держать на задачах из §4.1, где ошибку ловит тест.

## 7. Оговорка про экономику

Выгода возникает не от «делегирования мелочи». Постановка задачи и чтение ответа стоят токенов в любом случае, поэтому на короткой задаче экономия близка к нулю. Окупается ровно то, что перечислено в §4.2: большой вход, короткий выход, повторные прогоны по одному дереву файлов с попаданием в кеш.

Прежде чем расширять список, стоит посмотреть фактическую разбивку расхода — основная трата в студии приходится на чтение репозитория и циклы гейтов, а не на мелкие задачи.
