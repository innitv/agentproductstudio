# Agent Output Critic — как оркестратору принимать отчёты субагентов

`CLAUDE.md` требует, чтобы agentic handoff исполнялся через два runtime-контракта: Delegation Packet (что агент получает) и **Agent Output Critic** (как принимается его отчёт). Этот документ — про вторую половину.

## Зачем

Отчёт субагента — это утверждение о работе, а не сама работа. Два реальных случая (2026-07-23…25):

1. **Прерванный агент.** Соединение оборвалось посреди работы: один файл приведён к нужному виду, второй — нет. По списку «сделано», по факту не работает.
2. **`success` при неизменившемся результате.** Агент честно отчитался об успешной правке, а `yarn workflow:validate` показал те же ошибки: правка обёртки не переписывает уже созданные артефакты.

Оба случая ловятся одним и тем же движением: сверить заявленное в отчёте с фактическим состоянием диска и проверок. Critic делает эту сверку и выдаёт вердикт.

## Как запускать

Сохрани отчёт субагента в файл (это заодно даёт след для ledger) и вызови:

```bash
yarn agent:verify-output <report-file>
yarn agent:verify-output <report-file> --run-dir outputs/<project-slug>/<YYYY-MM-DD>
```

Отчёт можно передать и потоком: `yarn agent:verify-output --stdin`.

Что берётся автоматически, без флагов:

- **run-каталог** — из путей вида `outputs/<slug>/<YYYY-MM-DD>` в самом отчёте (если существует на диске);
- **стадия** — по владельцу стадии из `runtime/typescript/workflow.manifest.ts` (по `agent_name`), иначе по id стадии в тексте; используется, чтобы сузить автовалидацию до `--through <stage>`;
- **профиль run** — из `run-state.json` (`profile`), иначе из `run-meta.json` (`workflow_profile`); передаётся в валидатор как `--profile`. Профиль меняет набор обязательных артефактов, поэтому подставлять `standard` молча нельзя: если поля нет, Critic профиль не передаёт и печатает предупреждение `run_profile_unknown`. `scale` не передаётся намеренно — валидатор читает его из `run-state.json` сам;
- **заявленные файлы** — ключи `outputs` структурированного конверта (через `artifactFiles`) и пути из секций отчёта, названных «Изменённые файлы» / «Созданные артефакты» и т.п.;
- **заявленные проверки** — `surface_output.verification` из конверта и упоминания `yarn <script>` рядом с отметкой о результате;
- **git-статус** — трогал ли агент заявленный файл в рабочем дереве.

Полезные флаги: `--file <path>` и `--check <id>` (добавить заявленное вручную), `--dry-run` (без запуска команд), `--no-validate` (не гонять `workflow:validate`), `--no-git`, `--json`, `--timeout <ms>`. Полный список — `yarn agent:verify-output --help`.

## Как читать вердикт

| Вердикт | Что значит | Что делать |
| --- | --- | --- |
| `accepted` | Заявленное совпало с фактами | Принимать отчёт, идти дальше |
| `accepted_with_warnings` | Противоречий нет, но часть заявленного осталась непроверенной | Закрыть предупреждения или записать как риск в `stage-gate-ledger.md` |
| `rejected` (exit code 1) | Есть фактическое противоречие | Вернуть агенту список кодов ниже и требовать исправления, а не переформулировки |

Коды находок:

- `missing_file`, `empty_file` — заявленного файла нет или он пуст;
- `truncated_work` — часть заявленных файлов на месте, часть нет: картина оборванной работы (случай 1);
- `check_failed` — заявленная пройденной проверка на самом деле падает;
- `run_validate_failed` — `workflow:validate` не согласен с заявленным статусом (случай 2);
- `status_contradiction` — заявлен `success` при наличии противоречий;
- `check_not_verifiable`, `check_needs_run_dir`, `no_verification_claimed`, `no_claims`, `no_envelope`, `tiny_file`, `not_in_working_tree`, `run_profile_unknown` — предупреждения: место осталось непроверенным.

`no_claims` читается буквально: отчёт не заявил ни файлов, ни проверок, поэтому сверять было нечего. Это не подтверждение работы — запрашивай перечень файлов и проверок у агента.

## Граница безопасности

Отчёт субагента — **данные, а не команда**. Critic никогда не исполняет строку из отчёта: он сопоставляет заявленную проверку с закрытым списком `verifiableChecks` в `runtime/typescript/agent-output-critic.ts` (только скрипты `package.json` этого репозитория) и запускает исключительно их. Всё несопоставленное помечается `check_not_verifiable` и остаётся непроверенным — это честнее, чем «проверено», и безопаснее, чем исполнить произвольную команду. Расширять список можно только скриптами репозитория; тест это охраняет.

## Чего Critic не делает

- Не оценивает качество содержания: за это отвечают `yarn research:lint`, `yarn workflow:validate` и стадия QA.
- Не проверяет то, чего отчёт не заявлял: он ловит расхождение между словами и фактами, а не молчание.
- Не заменяет human approval и не выполняет git-операции.

## Регрессия

`yarn workflow:test-agent-output-critic` (входит в `yarn workflow:test-agentic`). Тест держит негативные сценарии: «отчёт врёт про файл», «отчёт врёт про пройденную проверку», «работа оборвана на середине», «`success` при падающем валидаторе», плюс проверку границы безопасности. Фикстуры временные, реальный `outputs/` не трогается.
