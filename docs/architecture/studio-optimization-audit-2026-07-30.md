## 2. P1 — сокращение `CLAUDE.md` откатилось за два дня

### Факт

`CLAUDE.md` грузится в каждую сессию **и в каждого субагента** (весь блок `claudeMd`).
Динамика по истории git (`git show <sha>:CLAUDE.md | wc -c`, байты):

| Дата | Размер | Событие |
|---|---|---|
| 2026-07-17 | 32 634 | |
| 2026-07-25 | 43 986 | |
| 2026-07-28 | 58 454 | пик |
| 2026-07-28 | 47 112 | **сокращение по аудиту 07-28 (−19 %)** |
| 2026-07-29 | 55 094 | **вернулось за два дня (+17 %)** |

Сейчас: 250 строк / 37 090 символов. Рекомендация первоисточника —
[под 200 строк](https://code.claude.com/docs/en/memory): «target under 200 lines per
CLAUDE.md file. Longer files consume more context and reduce adherence».

Где именно рост — раздел про библиотеку, `## 6.1`:

| Дата | §6.1 | |
|---|---|---|
| 2026-07-27 | 3 618 симв | |
| 2026-07-29 | 8 212 симв | **×2,3 за два дня** |

§6.1 — крупнейший раздел файла: 13,8 % объёма (~1 700 токенов в каждом контексте).

### Причина — не небрежность, а норма

Ретро 07-29 ([retro-a3-shadcn](retro-a3-shadcn-2026-07-29.md), находка 5) приняло
решение: «знание про библиотеку → `CLAUDE.md` §6.1, про процесс →
`claude-operating-rules.md`, про продукт → рядом с продуктом». Решение верное по сути
(до него знание про `shadow-xs` осело в продуктовом CSS). Но следствие: **каждый прогон
дописывает грабли библиотеки в файл, который грузится всегда**. Пять ограничений Plugin
API от 07-30 — уже следующая порция.

Механизма против роста нет: разовое сокращение неизбежно откатывается, потому что норма
предписывает складывать растущий класс знания именно сюда.

### Решение, которое у проекта уже работает

Асимметрия внутри собственной архитектуры: механика Figma **вынесена** в плагин
`figma-ds` (45 КБ в двух `SKILL.md`), в индексе остался указатель. Механика библиотеки
shadcn — того же класса знание — **осталась в индексе**. Плагин `ui-craft` (38 КБ) тоже
живёт вне контекста и доходит до субагентов через указатели в обёртках (коммит
`2a49ed8`).

То есть канал доставки уже построен и проверен: **плагин/skill + указатель в обёртках**.
§6.1 может уехать туда же, оставив в индексе решение владельца («основа — shadcn/ui») и
ссылку, а грабли уровня библиотеки — в навыке.

Тот же вывод у внешнего аналога: [obra/superpowers](https://github.com/obra/superpowers)
держит always-on контекст минимальным и грузит знание навыками по требованию, а не
монолитным ruleset — при том, что `.claude/rules/` существует.

### Отклонённая альтернатива: `.claude/rules/` с `paths:`

Выглядит как штатное решение (правила про фронтенд грузятся только при работе с
фронтендом) и **описано в официальной доке**. Проверил первоисточником до того, как
рекомендовать — не подходит:

- [#23478](https://github.com/anthropics/claude-code/issues/23478) — **closed as not
  planned**: path-scoped правила инжектятся только на Read, **не на Write/Edit**. Агент
  `frontend` файлы пишет, а не читает, — правило про тёмную тему до него не дошло бы.
- [#16299](https://github.com/anthropics/claude-code/issues/16299) — **open**, регрессия:
  правила грузятся в контекст на старте сессии независимо от `paths`, то есть экономии
  контекста нет вообще (у автора issue 28 правил вместо 5).
- Дополнительно: [#23569](https://github.com/anthropics/claude-code/issues/23569) —
  игнорируются при резолве через git worktree (проект worktree использует),
  [#17204](https://github.com/anthropics/claude-code/issues/17204) — документированный
  формат `paths` работает не везде, работает недокументированный `globs`.

Вывод: `.claude/rules/` в этот проект **не заводить**. Записано, чтобы механизм не
всплыл через месяц как «официальная рекомендация, которую мы почему-то не используем».

гарантирует.

Проверка `test-aggregator-coverage` покрывает саму себя: собственный скрипт обязан быть в
агрегаторе.

Решающий маркер — `yarn workflow:test-studio-hygiene`: команда создана в этой же сессии,
её нет ни в снимке `claudeMd`, ни в обёртке. `frontend` воспроизвёл её точно, вместе с

отсутствует, как и предупреждение про системную тёмную тему».

Вывод: **навык, созданный в текущей сессии, доезжает до субагента целиком и в тот же час.**
Механизм, выбранный для §6.1 вместо плагина, работает.

### 7.2. Побочная находка, которая важнее исходной проверки

Обе пробы уверенно цитировали §6.1 **в старой редакции** — с пунктами, удалёнными час
назад, — и ссылались на неё как на источник. Причина не в галлюцинации: три пробы с
дословными цитатами показали, что **блок `claudeMd` у субагента — снимок на момент старта
родительской сессии**, причём даже свежий спавн получает старый текст.

| Проба | Что увидела |
|---|---|
| Возобновлённый `prd` | старый §6.1 дословно |
| **Свежеспавненный** `prd` (после правки) | старый §6.1 дословно |
| `frontend` | старый §6.1; «имя `shadcn-library` в блоке `CLAUDE.md` не встречается вообще» |

При этом обёртка, её `skills:` и тела навыков читаются **актуальными** — закэширован ровно
один канал. Практическое следствие для студии: цикл «разбор прогона → правка правил → сразу
новый прогон» выполнит новые правила силами главной сессии, но субагентами — по старым, и по
их отчётам это неотличимо. Разложено по адресам: `delegation-lessons.md` (полный разбор),
`CLAUDE.md` §11.1, обёртка оркестратора, навык `rule-placement`.

Заодно это третий аргумент за адрес «навык, а не индекс»: помимо контекста и доставки,
правило в навыке начинает действовать сразу.
