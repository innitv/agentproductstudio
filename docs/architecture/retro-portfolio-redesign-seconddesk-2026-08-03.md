## Находки

### 1. Три дефекта каркаса прошли всю машинную приёмку

Прыжок имени в шапке (20 px против 36), разный старт первого заголовка (132 / 124 / 100
на 1440), неприжатый подвал (23 px хвоста, прыгал между страницами разной длины). Все
три нашёл человек переключением между страницами.

**Причина класса:** каждая страница по отдельности корректна. Витрина смотрит компонент
в изоляции, `vr:test` сверяет страницу с её СОБСТВЕННЫМ эталоном, `qa:mobile` берёт один
маршрут. Расхождение между страницами не принадлежит ни одной из них.

**Решение: машинная проверка.** `tests/portfolio-layout.check.mjs` (`yarn qa:layout`):
4 страницы × 3 вьюпорта, эталон — главная, допуск 1 px. В набор входит высокий вьюпорт
(1440×1200) — на коротком окне неприжатый подвал невидим — и две страницы одного типа с
разным объёмом содержимого.

**Негативный контроль (фактический вывод):**

```
fail · расхождений: 3
  [w1440] case: Заголовок стартует с 100 против 132 на главной
  [w1440-tall] case: Заголовок стартует с 100 против 132 на главной
  [w390] case: Заголовок стартует с 108 против 124 на главной
```

Разложено: `/ui-craft:build` §8.1 (процедура), `claude-operating-rules.md` → Machine
Acceptance Gate (четвёртая ось), обёртки `frontend` и `qa-review`.

### 2. Дубль между шапкой и подвалом прошёл приёмку по той же причине

Шапка и подвал несли ОДИН И ТОТ ЖЕ набор `contacts[]` — три одинаковые ссылки в двух
местах страницы. Дубль пришёл из спецификации (`screens.md`, строки `header` и `footer`)
и не был замечен ни на одной стадии.

Механизм тот же, что в находке 1, но внутри одной страницы: обе строки по отдельности
корректны, а их совпадение не проверяет никто. Аналитика при этом уже размечала
`placement: header/footer` — то есть дубль был описан как норма.

**Решение: норма.** Правило «сквозной элемент не повторяется в двух местах одной
страницы; если повторяется — у копий разные роли, и это записано» + проверка в истории
главной (`queryByTestId("pf-contact-tg") → null` рядом с `getByTestId("pf-footer-tg")`).

Машинной проверки в общем виде нет осознанно: «одинаковый набор ссылок» формализуется
только для конкретного продукта, а универсальная эвристика дала бы ложные срабатывания
на легитимных повторах (логотип в шапке и в подвале — норма).

### 3. Правка файла самописным скриптом продублировала 16 696 символов CSS

При удалении осиротевшего правила из `portfolio.css` скрипт вырезал отрезок по
`indexOf`, где конечная позиция оказалась МЕНЬШЕ начальной. Вместо удаления получилась
вставка: `s.slice(0, start) + s.slice(end)` при `end < start` дублирует `[end, start)`.
Файл вырос с 17 668 до 34 364 символов, `.pf-frame` встречался четыре раза вместо двух.

Отрицательная дельта («удалено символов: -16696») была видна в выводе сразу — но
скрипт уже записал файл. Файл был untracked, git не помог; восстановление потребовало
вычислять длину периода дубля и искать позицию, где `s[i..i+D] === s[i+D..i+2D]`.

**Решение: норма.** Точечная правка файла — только `Edit` с проверкой уникальности
совпадения. Самописный скрипт со срезами допустим лишь когда файл под контролем git
(есть откат) ИЛИ когда скрипт сначала печатает предполагаемое изменение и только
следующим вызовом пишет. Отрицательная дельта размера — стоп-сигнал, а не курьёз.

### 4. Новая проверка мерила не ту величину и падала на корректном коде

Проверка ровности ряда метрик сравнивала абсолютный `top` значений. На ширине витрины
1160 сетка встаёт в две колонки, и разный `top` там означает законную вторую строку —
проверка падала на здоровом коде.

Правильная величина — СМЕЩЕНИЕ значения от верха своей ячейки: именно оно и ломалось,
когда двухстрочное число выравнивалось по низу и уезжало вверх.

**Решение: норма.** Формулировать проверку от МЕХАНИЗМА дефекта, а не от его симптома в
одном вьюпорте. Если величина меняется по легитимной причине (перенос сетки,
адаптивность), она не годится в предмет проверки — нужна инвариантная.

### 5. Метрика «дорогих находок» показала 0 при фактических 13

Разметка `<!-- retro: found_by=… -->` не поставлена ни под одним заходом, поэтому
эвристика отнесла к `unknown` все 6 распознанных заходов. Фактически владелец нашёл
глазами все 13 правок цикла 8.5b, включая три дефекта из находки 1.

Побочный эффект: цифра «0 дорогих находок» выглядит как отличный результат, тогда как
означает обратное — весь контроль качества держался на человеке.

**Решение: норма + отказ от машинной части.** Норма: заход, вызванный замечанием
человека, размечается `found_by=user_review` в момент захода. Машинно вывести канал
нельзя — источник живёт в переписке, а не в артефактах; попытка угадывать по тексту
заголовка уже даёт 0 из 6.
