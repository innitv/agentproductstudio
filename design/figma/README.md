# Figma design systems

Эта папка хранит долгоживущие локальные индексы Figma дизайн-систем. **Ни один из них не является дефолтом.** Дизайн-система по умолчанию — shadcn/ui в коде (`apps/frontend/src/components/shadcn/`, CLAUDE.md §6.1); токены — DTCG в `design/tokens/`; витрина — Storybook. Индекс здесь нужен только тогда, когда работа реально идёт по чужому Figma-файлу, переданному пользователем.

Актуальный состав задаёт `registry.json` — он единственный источник правды о том, какие индексы существуют. Валидатор (`yarn validate:config`) проверяет реестр структурно: для каждой объявленной системы обязаны существовать файлы, которые она сама объявила в `paths`. Состав систем можно менять свободно; ошибкой считается только рассинхрон — запись есть, а файлов нет. Пустой список систем законен.

## Что сейчас в реестре

**Рабочих дизайн-систем в реестре нет** (состояние на 2026-07-27). Единственная запись — `a3-finance-visitka` — это фриланс-поставка макетов конкретного проекта, а не DS: токенов там нет, часть component set дефектна, прямой `reuse` запрещён самой записью. Не выбирай её как `selected_design_system_slug` по умолчанию только потому, что она единственная.

Прежнее деление индексов на роли `working` и `reference` упразднено вместе с архивацией индексов:

- роль `working` («на чём строить») перешла к shadcn/ui в коде — выбирать её в этом реестре больше не из чего;
- роль `reference` («как правильно устроена и подана DS») перешла к плагину `figma-ds`: канон читается из `/figma-ds:standard`, механика — из `/figma-ds:build`. Держать для этого копию чужого Figma-кита не нужно, и индекса M3 в реестре больше нет.

Поле `role` в `registry.json` остаётся допустимым для будущих записей, но сейчас ни на что не влияет.

## Правило выбора

Перед Figma handoff, frontend implementation или canvas write агент выбирает `design_system_mode` (полный текст гейта — `agent-pack/workflows/claude-operating-rules.md` §5):

- `reuse` — **умолчание**: использовать существующую систему без дублирования primitives/components. Для нового product UI это shadcn/ui в коде; зарегистрированная Figma-система из `registry.json` — только когда работа действительно идёт по переданному пользователем файлу.
- `extend` — использовать зарегистрированную foundation и добавить только подтвержденные gaps.
- `product_specific` — создать новую продуктовую систему после visual calibration.
- `bespoke` — не строить библиотеку заранее, выносить только доказанные повторы.

Если выбран `reuse|extend` **внешней Figma-системы**, укажи `selected_design_system_slug` из `registry.json`. Для дефолтного маршрута (shadcn/ui в коде) это поле не заполняется — его пустота не является пробелом и не требует ingest.

## Локальный индекс

Для общей Figma DS агент работает с локальным индексом:

- `source.md` — источник и scope.
- `_scan/census.md` — перепись страниц, component sets, компонентов и variables.
- `_scan/manifest.md` — порции ingest со статусами `pending|done|blocked`.
- `foundation.md` — variables, semantic aliases, modes.
- `components.md` — компактная карта компонентов с Node ID.
- `components/<category>.md` — deep profiles: slots, variants, anatomy, sizes.
- `component-contracts.json` — machine-readable Figma → frontend contract.
- `code-connect-fallback.md` — mapping, если Code Connect недоступен.

После ingest агент читает индекс, а не весь Figma-файл. В Figma нужно ходить только для missing nodes, refresh, write или verification.

## Архив индексов

Дизайн-система по умолчанию — **shadcn/ui из официального реестра, в коде** (`apps/frontend/src/components/shadcn/`, см. CLAUDE.md). Индексы Figma-DS, переставшие быть источником правды, переезжают в `archive/design-systems/<slug>/` — тот же смысл, что у остального корневого архива: файлы остаются на диске и в истории git, но не публикуются из рабочего дерева. Запись такой системы удаляется из `registry.json`: реестр описывает индексы, доступные сейчас, а не всё, что когда-либо индексировали.

Архивировано 2026-07-27:

- `a3-design-system` — пилотный индекс Figma-файла A3. Дизайн-системой больше не пользуемся. Код компонентов A3 и его токены удалены из рабочего дерева 2026-07-28 вместе с демо, на котором они держались (остаются в истории git).
- `shadcn-ui-components-2026` — community-кит shadcn/Tailwind. 22 компонента против 61 в официальном реестре, и это не тот кит, что рекомендован на ui.shadcn.com/docs/figma.

Вернуть индекс в работу = переместить каталог обратно в `design/figma/<slug>/` и восстановить запись в `registry.json`.
