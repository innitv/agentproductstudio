# Токены дизайн-системы A3 (DTCG)

Здесь живёт **источник правды для токенов**. Значения задаются в этих JSON-файлах,
а `apps/frontend/src/styles/tokens.generated.css` и Figma-экспорт из них собираются.
Figma больше не является источником значений: локальный baseline
`design/figma/a3-design-system/token-map.md` остаётся справочной картой происхождения.

## Формат

**DTCG 2025.10** — первый стабильный релиз спецификации (28.10.2025). Ключевое
отличие от более ранних черновиков: `color` и `dimension` — структурированные
объекты, а не строки.

```jsonc
{ "$type": "color",
  "$value": { "colorSpace": "srgb", "components": [0.325, 0.592, 0.921], "alpha": 1, "hex": "#5397eb" } }

{ "$type": "dimension", "$value": { "value": 16, "unit": "px" } }
```

Черновик на `designtokens.org` помечен «preview draft, do not implement» —
ориентироваться на него не нужно.

Алиасы записываются как `{group.token}` и всегда сопровождаются явным `$type`:
наследование типа по ссылке допустимо спецификацией, но импорт в Figma Variables
надёжнее работает с явным типом.

## Тиеры

Ссылки идут только вниз: `component → semantic → primitive`.

| Тир | Каталог | Токенов | Содержимое |
|---|---|---:|---|
| primitive | `primitive/` | 292 | Сырые context-free значения: 12 палитр × 17 ступеней, базовые цвета, шкалы spacing/size/radius, размеры и начертания шрифта, тени |
| semantic | `semantic/` | 17 | Роли: текст, поверхности, границы, бренд-цвета, радиусы по назначению (`inputs`/`buttons`/`controls`) |
| component | `component/` | 495 | Значения, привязанные к конкретному компоненту (18 файлов) |
| compat | `compat/` | 216 | Устаревшие алиасы `--a3-base-*` / `--a3-palette-*`, помеченные `$deprecated` |

`compat` — не тир канона, а слой обратной совместимости: он позволяет не
переписывать существующую вёрстку и исключён из Figma-экспорта.

### Известный gap

Semantic-слой пока тонкий: большинство component-токенов ссылается напрямую на
primitive, а 281 цветовой литерал записан в component-слое сырыми значениями
(из них 200 уникальных). Самые частые повторы — `rgba(124, 138, 158, 0.15)`
(disabled-фон, 12 употреблений), `rgba(124, 138, 158, 0.8)` (disabled-текст, 12),
`rgba(83, 151, 235, 0.12)` (accent subtle, 6). Это кандидаты в semantic-роли.
По канону (`/figma-ds:standard`, раздел 1) component должен ссылаться на semantic,
а не на primitive — расширение слоя требует продуктового решения об именах ролей
и выполняется отдельным шагом.

## Сборка

```bash
yarn tokens:build
```

Собирает две платформы:

| Выход | Назначение |
|---|---|
| `apps/frontend/src/styles/tokens.generated.css` | CSS-переменные для фронтенда; подключён через `@import` в `apps/frontend/src/styles.css` |
| `design/tokens/figma/light.json` | DTCG на mode для импорта в Figma Variables |

Конфигурация — `tooling/tokens/sd-config.mjs`, кастомные хуки — `tooling/tokens/sd-hooks.mjs`.

### Почему кастомные трансформы

- `name/kebab` разрушает сегменты `status-01`, `0-5x`, `2xs` — нужно точное
  соответствие пути токена имени CSS-переменной;
- `color/css` выводит hex и `rgb(% % % / a)`, а baseline фронтенда написан в `rgba()`;
- `shadow/css/shorthand` дописывает `spread` и меняет формат цвета;
- `fontFamily/css` квотит одинарными кавычками.

### Figma-экспорт

У Style Dictionary **нет** встроенного формата `json/dtcg` (только `json`,
`json/nested`, `json/flat`, `json/asset`), поэтому формат `json/dtcg-a3` написан
вручную — он берёт `token.original.$value`, сохраняя алиасы неразвёрнутыми.

Из экспорта исключены `shadow` и `fontFamily`: Figma Variables поддерживают только
COLOR, FLOAT, STRING и BOOLEAN, композиты переменными не становятся. Исключён и
`$deprecated`-слой совместимости. В экспорте 780 токенов.

Файл — один на mode. Сейчас mode один (`light`); список задаётся константой
`MODES` в `tooling/tokens/sd-config.mjs`. Тёмная тема добавляется как второй mode
на **semantic**-слое, primitives при этом не дублируются.

## Защита от тихого изменения значений

`design/tokens/baseline/styles-root.baseline.json` — снимок блока `:root` из
`styles.css` на момент миграции (1020 переменных). `yarn tokens:build` сверяет с
ним результат и **падает**, если состав переменных или их вычисленные значения
разошлись. Отличия в записи (`#071f3d` против `rgba(7, 31, 61, 1)`) показываются
отдельным списком и сборку не блокируют.

Дополнительно `tests/playwright/tokens-parity.spec.ts` читает вычисленные значения
всех переменных из реального документа в браузере — это ловит проблемы каскада и
порядка `@import`, которых текстовая сверка не видит.

Изменение baseline допустимо только вместе с осознанным решением поменять значения
во фронтенде.

## Как менять токены

1. Правка в `design/tokens/**.json`.
2. `yarn tokens:build` — если значение изменилось намеренно, обновить baseline тем же коммитом.
3. `yarn build` и `yarn qa:studio`.
